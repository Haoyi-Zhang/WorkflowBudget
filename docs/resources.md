# Resource accounting and reproduction boundary

The environment intake inspected CPU, memory, swap, and writable space once without a stress test. It exposed a four-core quota and a 4 GiB memory ceiling with no swap. Scientific chunks deliberately use one worker, at most 3 GiB address space, and 35 CPU-seconds per process. No parallel pool, GPU, external scientific compute, model call, network experiment, private service, or new human evidence is used.

The final validation comprises eighteen instrumented suites: the theory-construction suite, independent path-set reconciliation, two-node suite, twelve three-node blocks, workflow suite, dead-key stress suite, and selector suite. `results/summary.json` records 31.110704 process CPU-seconds including process startup, 15.733491 inner campaign CPU-seconds, and 152,548 KiB maximum suite RSS. The ten-case pilot and unit-test process measurements are recorded separately. These figures describe the recorded in-place run, not future hardware or the whole interactive research session.

The final in-place full wrapper executed 22 child commands in 30.369 wall-seconds, using 38.318846 child CPU-seconds and 263,656 KiB aggregate maximum child RSS. In a clean-copy audit, isolated quick mode completed 6/6 commands in 4.416 wall-seconds with 6.515616 child CPU-seconds and 98,988 KiB maximum child RSS while changing zero canonical files; full mode completed 22/22 commands in 30.555 wall-seconds with 38.510457 child CPU-seconds and 263,652 KiB maximum child RSS. The audit also executed all 26 tests, the bibliography gate, the producer-to-checker command-line example, and an explicit check that optimized Python is rejected before claim-critical assertions can be elided. It reconciled 48 deterministic result files (23 JSON, 16 JSONL, eight CSV, and one generated TeX table); runtime and RSS fields were normalized away. `verify_delivery.py` performs this audit, and `results/clean-reproduction.json` records its result. Filesystem extraction, orchestration, and runtime variability can change timing and memory values. Compilation, literature browsing, visual inspection, and packaging are not presented as algorithm runtime.

For planning, 600 CPU-seconds were conservatively allocated to preliminary and uninstrumented development. This is an allowance, not a measurement. The complete measured and allocated work remains far below the 8 CPU-hour ceiling and leaves the reserved repair/reproduction quarter intact.

Exact semantic reproduction means that deterministic controller/workflow rows, verdicts, least budgets, proof acceptance flags, state counts, width bounds, theory-construction outcomes, generated cases, certificates, CSVs, and LaTeX table inputs agree. CPU time, wall time, RSS, PDF timestamps, and ZIP metadata are variable and excluded from byte-level comparison. A successful command establishes execution and data reconciliation; it does not constitute independent scientific review or a machine-checked proof.
