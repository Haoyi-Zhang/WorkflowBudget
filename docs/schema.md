# Controller and certificate format

JSON objects have exactly the fields described here; extra fields are rejected by the checker. Duplicate object keys are rejected on file input. A Boolean JSON literal is not accepted as an integer zero or one. The checker is a local scientific tool, not a parser-security claim.

## Pair

A pair has `left` and `right`. Each controller has:

- `keys`: list of distinct nonempty strings, at most 64, each at most 64 characters.
- `results`: similarly distinct labels, at most eight.
- `start`: integer node index. It need not be zero.
- `nodes`: nonempty list of at most 2,048 instructions.

Both ordered alphabets must be identical. Node indices are zero-based. Every target of a node at index i must be greater than i and less than the node count. Unreachable nodes and equal read successors are allowed. Instructions are exactly `{"op":"halt"}`, `{"op":"step","next":j}`, `{"op":"emit","result":r,"next":j}`, or `{"op":"read","key":k,"zero":j0,"one":j1}`. Result/key fields are indices in the corresponding alphabets. Halt is padded operationally, but carries no outgoing JSON edge.

See `inputs/case-04.json` for a complete example. Empty alphabets are permitted when no instruction requires their elements.

## Proof state

A state is a five-element list `[left_node, right_node, left_mask, right_mask, memory]`. Each result mask is an integer from zero to `2**len(results)-1`. `memory` is a list of `[key_index, value]` bindings, strictly increasing in key index. Values are integer zero or one. Each stored key must belong to the checker-computed union of future reads at the two current nodes. No duplicate binding, reordered key, non-live key, or invalid mask is accepted.

A proof record is exactly `{"state":state,"rank":integer}`. The proof's `nodes` list has between one and 200,000 records, with no repeated state. Every supplied state must have equal output masks. The initial state is `[left.start,right.start,0,0,[]]`, must occur, and must have rank zero.

## Positive certificate

A positive object has exactly `kind` (value `equivalent`) and `nodes`. All ranks are integers in `[0,H]`, where H is the larger controller node count; ranks are bounded annotations, not used as distances. Every compatible successor of every supplied state must occur in `nodes`. This includes the self-successor when both controllers have halted. The checker enumerates up to four local keyed assignments and recomputes restriction, so the producer cannot supply a fraudulent transition list.

## Negative certificate

A negative object has exactly `kind` (value `inequivalent`), `budget`, `world`, and `nodes`. The budget t is an integer from one to H. The world is one integer bit per key. Direct checker replay must produce different masks at t. All proof ranks belong to `[0,t-1]`. For every state of rank below t-1, every compatible successor must appear and have rank at most the source rank plus one. Rank-t-1 boundary states have no successor obligation. This universally certifies safety at every smaller budget, including for worlds other than the supplied witness.

File admission limits are 8 MiB for a controller pair and 64 MiB for a certificate. Invalid file/JSON/structural/semantic data are rejected. API calls to `check` take already decoded objects and therefore do not apply the file-byte or duplicate-object-key checks themselves. The producer state cap and checker certificate cap are separate; exceeding one is inconclusive, not a successful equivalence result.

## Reproduction data

Each comparison JSONL row records its deterministic index, verdict, least budget (null for equality), product counts, oracle agreement, certificate acceptance, and suite-specific dimensions. The raw controller suites use ordered pairs; workflow policy pairs are unordered. Intermediate campaign certificates are checked in memory and regenerated by the deterministic constructors rather than all stored. Ten pilot certificates are serialized for direct replay. Stress rows compare live projection with a retain-all parameter in the same producer and do not claim oracle enumeration or proof certificates for that ablation.

`src/report.py` reconciles counts, disjoint block IDs, expected suite dimensions and agreement flags before creating CSV summaries and the LaTeX validation table. Its generated files are derivations, not replacement evidence. Resource measurements describe the recorded run; exact bytes of timings and RSS need not reproduce.
